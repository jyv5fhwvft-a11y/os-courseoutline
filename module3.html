L10 Lecture 10: Relocation Models & Base-and-Bound Isolation

🎯 Objective

Calculate valid physical memory address locations from logical addresses given specific Base and Bound hardware register limits, and catch security bounds exceptions.

🛑 Prerequisites

Module 2 (All Lectures), hardware registers.

🎪 Analogy 1 (Everyday Life)

The Hotel Room Numbering Illusion. Imagine a large hotel resort. Every single guest checking in receives an automated room booklet that says they are staying in "Room 100" (The Logical Address). When they go to find their room, they must use a master keycard lock. The hotel's physical architecture silently maps each guest's "Room 100" to a completely different floor. For Guest A, the room starts at real room 500 (Base Register = 500) and they only paid for a small 10-room suite (Bound Register = 10). If Guest A tries to open "Room 115", their keycard fails because it exceeds their bound boundary. Guest B's "Room 100" starts at real room 800. They both think they occupy address 100, but the front desk (The OS) relocates them seamlessly.

💻 Analogy 2 (Pure Technical)

An Offset Array Pointer Index. Base-and-bound protection behaves identically to a safe compiler runtime wrapper around a raw byte array pointer. The Base register functions as the absolute starting array memory address (&array[0]), while the Bound register acts as a strict if (index >= length) array bounds check.

🔗 System Cohesion Matrix

  • Relies On: L02 (Dual-Mode Barrier) — Relies on Ring 0 privileges to lock the physical Base and Bound registers so user threads cannot change their own memory space walls.
  • Feeds Into: L11 (The Paging Model) — Serves as the historical precursor that proves contiguous variable-sized memory allocations lead to severe external fragmentation, driving the invention of fixed-size paging.

🔍 Core Breakdown

To achieve multiprocessing, memory must be virtualized. The earliest model used Dynamic Relocation via hardware registers. When a program is loaded into RAM, the kernel notes its physical starting location into a hardware Base Register and its maximum allowable block size into a Bound Register.

The CPU uses these to evaluate every instruction at runtime: Physical Address = Logical Address + Base. If the logical address is less than zero or greater than or equal to the Bound register, the hardware interrupts execution instantly and throws a segmentation fault trap.

🏷️ Lexicon / Terms

  • Logical AddressA virtual address generated by the compiler and CPU instruction stream during development and runtime execution.
  • Physical AddressThe actual, hardware-wired slot location inside the physical RAM chip matrix.
  • Base RegisterA physical CPU tracking chip that stores the absolute starting physical address of a program's active memory slot.
  • Bound RegisterA physical hardware safety register tracking the maximum size allocation block granted to a running process context.

🛠️ Practical Example

Mathematical Relocation Problem: A process has a hardware configuration setup where Base = 14000 and Bound = 2000.

Scenario A: The CPU attempts to fetch an instruction from Logical Address 450. Is it safe? 450 < 2000 (Passes Bound Check). Physical Destination = 450 + 14000 = 14450. (Valid execution).

Scenario B: The CPU attempts a memory operation on Logical Address 2100. Is it safe? 2100 ≥ 2000 (Exceeds Bounds!). The hardware immediately triggers a CPU exception trap, terminating the task with a Segmentation Fault panic.

🎯 Interactive Classroom Activity

The Chalkboard Relocation Machine. Draw a grid of numbers 0 to 100 on the board to represent physical RAM. Hand two students dry-erase markers. Assign Student 1 a Base of 20 and a Bound of 10. Assign Student 2 a Base of 50 and a Bound of 15. Shout out logical addresses like "Student 1, modify location 5!" or "Student 2, access location 20!" Have the class audit if the student writes on the correct physical grid square or if they must freeze and yell "Segmentation Fault!"

L11 Lecture 11: The Paging Model & Fixed-Size Translation Matrix

🎯 Objective

Trace a 32-bit virtual address stream into its corresponding physical address destination using a multi-level page table schematic layout.

🛑 Prerequisites

L10 (Relocation Models), binary-to-hex conversion tracking, basic algebra.

🎪 Analogy 1 (Everyday Life)

The Phonebook Indexed Ledger Page. Imagine trying to read a giant encyclopedic novel that has been completely ripped apart, separated into single loose paper pages, and scattered randomly across different drawers in a room. To read the book in order, you need a single index card cheat-sheet—the Page Table. The book is written in logical order: Chapter 1 is on Page 0, Chapter 2 is on Page 1. The index cheat-sheet tells you: "Page 0 is hiding in Drawer #4" (Physical Frame 4), and "Page 1 is hiding in Drawer #99" (Physical Frame 99). You can read smoothly because your index map fixes the scattered physical chaos transparently.

💻 Analogy 2 (Pure Technical)

A Key-Value Hash Map Pointer Array lookup. Paging functions exactly like a hardware-level multi-dimensional array lookup table, where the high-order binary bits of an address stream are peeled off to serve as the index key to return a raw data pointer address.

🔗 System Cohesion Matrix

  • Relies On: L05 (Process Anatomy) — Every independent process PCB structure must preserve a pointer to its own unique isolated physical Page Table location.
  • Feeds Into: L12 (TLB Acceleration) — Address translation requires a nested memory access path, necessitating a specialized hardware cache to maintain high-speed throughput.

🔍 Core Breakdown

Base-and-bound models cause severe External Fragmentation (wasted space between allocations). Paging fixes this by chopping memory into fixed-size units. Virtual memory is split into Pages, and physical memory is split into identical matching blocks called Frames.

A virtual address is split into two components: a Page Number (p) and an Offset (d). The hardware Memory Management Unit (MMU) grabs the Page Number, checks it against the process's Page Table to find the corresponding physical Frame Number (f), and appends the unchanged Offset to land precisely on the correct physical byte. This completely eliminates external fragmentation.

🏷️ Lexicon / Terms

  • PageA fixed-size contiguous block of virtual address space allocated by the compiler and operating system kernel.
  • FrameA physical, hardware-wired block of real RAM storage matching the exact byte dimensions of a system page slot.
  • Page TableThe authoritative data matrix structure held in kernel space that maps a process's virtual page numbers to real hardware frame slots.
  • Internal FragmentationWasted memory space that occurs when a process requests a buffer that doesn't completely fill out the final allocated fixed-size page block boundaries.

🛠️ Practical Example

Basic Paging Mapping Walkthrough: Assume a system has a small 16-byte virtual address space with 4-byte pages. The virtual address is 4 bits wide: 2 bits for Page Number, 2 bits for Offset.

We want to translate Virtual Address 1101 in binary.

Step 1: Separate the components. The first two bits 11 = Page Number 3. The last two bits 01 = Offset 1.
Step 2: Lookup Page 3 in our Page Table matrix array. The table says: Page 3 -> Frame 5 (Binary 101).
Step 3: Assemble the final physical destination. Combine Frame 101 with the original unchanged offset 01 = Physical Address 10101 (Real decimal address 21).

🎯 Interactive Classroom Activity

The Multi-Level Page Walk Board Routing Game. Draw a two-tier array grid layout on the main classroom board representing a Page Directory and a secondary Page Table. Hand a student a card displaying a hexadecimal virtual address string. Have them act as the hardware MMU chip, tracing their finger from the first bits to the directory block, down to the frame cell pointer, to prove they can resolve the physical destination by hand.

L12 Lecture 12: TLB Acceleration & Caching Math

🎯 Objective

Calculate Effective Access Time (EAT) equations using hit-rate variables, hardware cache check latencies, and physical RAM access latency boundaries.

🛑 Prerequisites

L11 (The Paging Model), basic algebra equations.

🎪 Analogy 1 (Everyday Life)

The Sticky Note on the Computer Monitor. Imagine you work as a researcher who constantly needs to look up phone numbers in a massive 1,000-page directory book kept across the room (The Page Table in RAM). Every single time you want to make a call, walking across the room to check the book slows you down heavily. To solve this, you stick a small piece of paper right next to your telephone (The TLB Cache). When you look up a number for the first time, you write it on the sticky note. The next time you call that exact same person, you don't walk across the room; you glance at the sticky note instantly (TLB Hit). You only walk to the heavy phonebook if the note is missing the name (TLB Miss).

💻 Analogy 2 (Pure Technical)

A Local Storage Key-Cache Web Proxy. A Translation Lookaside Buffer functions identically to an ultra-fast hardware register cache layer that intercept routes recursive database index scans using local static memory chips.

🔗 System Cohesion Matrix

  • Relies On: L11 (Paging Model) — Integrates directly inside the bit-shifting logic of the MMU address translation processing pathway.
  • Feeds Into: L13 (Virtual Memory) — A TLB miss pattern can cascade down to trigger a complete disk-drive swap block search if a page is marked as absent.

🔍 Core Breakdown

Paging introduces a severe performance penalty: every memory access costs two trips to physical RAM (one trip to read the page table entry, and a second trip to read the actual target data byte). This slows systems down by 50%.

To resolve this, hardware designers integrated a Translation Lookaside Buffer (TLB) directly into the CPU MMU. The TLB is an ultra-fast associative hardware cache that stores recent virtual-to-physical address translations. When a virtual address is processed, the TLB is checked in parallel. If a match occurs (TLB Hit), the translation is resolved instantly, bypassing the page table memory trip completely.

🏷️ Lexicon / Terms

  • Translation Lookaside Buffer (TLB)A specialized hardware cache embedded inside the CPU MMU dedicated exclusively to accelerating virtual address mapping scans.
  • TLB Hit RateThe statistical percentage frequency representing how often a target virtual address translation is successfully resolved inside the fast cache layer.
  • TLB MissA scenario where a virtual address is absent from the TLB, forcing the system to perform a slower, multi-step page table walk across main RAM.
  • Effective Access Time (EAT)The calculated average operational time cost paid by a system to resolve a memory data request stream.

🛠️ Practical Example

Effective Access Time Calculation Equation Formulation: Assume main memory access latency costs 100ns, checking the hardware TLB cache chip costs 1ns, and our system has a verified 90% TLB Hit Rate.

EAT = (HitRate × [TLBLookup + MemoryAccess]) + (MissRate × [TLBLookup + TwoMemoryAccesses])
EAT = (0.90 × [1ns + 100ns]) + (0.10 × [1ns + 100ns + 100ns])
EAT = (0.90 × 101ns) + (0.10 × 201ns) = 90.9ns + 20.1ns = 111ns

(This shows that with a high hit rate, our average memory trip costs only 111ns instead of the unaccelerated 200ns double-trip penalty).

🎯 Interactive Classroom Activity

The Real-Time Latency Math Challenge. Write the EAT equation on the projector. Change the Hit Rate live from 95% down to 20% (simulating heavy cache thrashing code). Have students calculate and plot the resulting curve to visually discover how writing cache-unfriendly array looping code can choke execution performance.

L13 Lecture 13: Virtual Memory, Demand Paging & Page Replacement Primitives

🎯 Objective

Trace a page reference execution string manually through FIFO and LRU page replacement pipelines, and accurately log final Page Fault counts.

🛑 Prerequisites

L11, L12, basic logic queues.

🎪 Analogy 1 (Everyday Life)

The Limited Desk and the Library Storage Stacks. Imagine you are studying in a massive university library. Your study desk can only fit exactly 3 books at a time (Physical Frame Allocation). You are currently writing an essay that references 10 different books (Virtual Address Space). You start working; you look for Book A on your desk. It isn't there! This is a Page Fault. You must pause your work, wait for a runner to fetch Book A from the deep basement storage stacks (The Hard Disk/Swap Space), and drop it onto your desk. When your desk fills up completely and you need a 4th book, you must choose one current book to throw off your desk and send back to the basement stacks (Page Replacement Policy).

💻 Analogy 2 (Pure Technical)

An On-Demand Network Streaming Video Buffer. Demand paging matches media streaming platforms that load only the immediate 10 seconds of a massive 4K movie file into active memory, swapping old data blocks clear out of local cache boundaries when the player scrubs to a new section.

🔗 System Cohesion Matrix

  • Feeds Into: Module 4 (Process Synchronization) — Because virtual memory allows multiple concurrent threads to securely share specific page entries, it sets the stage for race condition contentions.
  • Feeds Into: Module 5 (File & Storage Management) — Swapping unmapped dirty pages out of RAM requires directly orchestrating raw block writes to disk storage partitions.

🔍 Core Breakdown

Demand Paging allows an operating system to execute an application even if its total memory footprint is vastly larger than the computer's physical RAM chip. The kernel leverages a Present/Absent Bit inside each page table entry. If a thread attempts to access a virtual page marked as absent, the hardware MMU cannot translate it and triggers a specialized Page Fault Exception Interrupt.

The kernel intercepts this fault, halts the thread, locates the missing block inside the disk Swap Space, copies the page into an empty physical frame, updates the page table bit, and rewinds the CPU to retry the instruction. If no physical frames are vacant, a replacement algorithm—such as FIFO (First-In, First-Out) or LRU (Least Recently Used)—is invoked to evict a page.

🏷️ Lexicon / Terms

  • Demand PagingAn optimization mechanism where virtual pages are loaded into physical RAM strictly on-demand only when an active instruction requests them.
  • Page FaultA valid hardware exception interrupt triggered when a thread attempts an operation on a page marked as absent from physical RAM.
  • Swap SpaceA designated raw block sector layout on a hard drive or SSD used to cache evicted virtual page overflows.
  • ThrashingA critical system failure state where a machine spends more time continuously swapping blocks back and forth to disk than executing actual instruction paths.

🛠️ Practical Example

Page-Reference String FIFO vs LRU Tracing Comparison Exercise: Given a 3-frame allocation pool and the reference string: 1, 2, 3, 4, 1, 2.

FIFO Execution Trace:
Access 1, 2, 3 -> Loads into frames [1, 2, 3] -> 3 Page Faults
Access 4 -> Evicts oldest page (1) -> Frames become [4, 2, 3] -> 4th Page Fault
Access 1 -> Evicts next oldest (2) -> Frames become [4, 1, 3] -> 5th Page Fault
Access 2 -> Evicts next oldest (3) -> Frames become [4, 1, 2] -> 6th Page Fault (Total Faults = 6).

LRU Execution Trace:
Access 1, 2, 3 -> Loads into frames [1, 2, 3] -> 3 Page Faults
Access 4 -> Evicts least recently used page (1) -> Frames become [4, 2, 3] -> 4th Page Fault
Access 1 -> Evicts least recently used page (2, since 3 was touched after 2) -> Frames become [4, 1, 3] -> 5th Page Fault
Access 2 -> Evicts least recently used page (3) -> Frames become [4, 1, 2] -> 6th Page Fault (Total Faults = 6).

🎯 Interactive Classroom Activity

The Human Reference String LRU Simulation. Line up three empty chairs at the front of the room to serve as a 3-frame RAM block. Call out numbers from a string. Have students carrying matching numeric cards rush up to sit in an empty chair. When a student arrives and all chairs are full, instruct the class to evaluate who has been sitting in their chair the longest without being touched, and make that student vacate their seat back to the lobby.
